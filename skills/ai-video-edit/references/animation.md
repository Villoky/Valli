# Анимации в HyperFrames

HyperFrames (HeyGen) — скилл для Claude: собирает видео из веб-страницы и сам рендерит. Нужен Node.js.
```
npx skills add heygen-com/hyperframes --full-depth --yes
```
`--full-depth` берёт свежий main, а не отстающий кэш реестра. Программа монтажа для анимаций не нужна: готовый MOV ProRes 4444 ложится в любой редактор.

Анимацию подгоняют под текст, а не текст под анимацию. Все тайминги — массивом `T` в начале скрипта, у каждого подписано слово, к которому он привязан.

## Восемь правил «дорогой» анимации
1. **Всё от времени t.** Сцену описывает одна функция `render(t)`. Никаких CSS-переходов, таймеров и памяти о прошлом кадре — любой кадр рендерится и проверяется отдельно.
2. **Пружины вместо кривых.** Крупные объекты без перелёта (демпфирование от 0,9), мелкие с лёгким перелётом (0,7–0,8). Код — `assets/phys.js`.
3. **Одна форма вместо череды появлений.** Элемент перетекает из состояния в состояние: чип вырастает в карточку, бусина едет по рельсу, счётчик заполняет полосу.
4. **Живая камера.** Мир медленно наезжает или дрейфует, кадр не стоит дольше 2 с.
5. **Свет вместо заливок.** На фоне два мягких цветных пятна, плывут по синусу от t.
6. **Motion blur.** Рендер 100 fps → ffmpeg сливает каждые 4 кадра → 25 fps. Самый дешёвый способ сделать картинку «дорогой».
7. **Вход элемента.** Размытие 12→0, прозрачность, сдвиг 16–46 px на пружине. Дописанный текст держится ≥1,5 с.
8. **Типографика.** Один шрифт, табличные цифры, ≥22 px. Заглавные только в мелких надзаголовках, с разрядкой.

## Промпт «сделай плашку в этом стиле»
Подставь значения в угловых скобках, приложи `assets/phys.js`.
```
Сделай анимированную плашку для моего ролика в HyperFrames: 1920×1080, 25 fps, длина <N> секунд.
Слова, под которые она идёт: «<фраза из сценария>».
Что на экране: <опиши одну форму и как она превращается по шагам>.
Техника строго: 1) всё, что видно, считается в одной функции render(t) от времени t, GSAP только двигает прокси {t} от 0 до конца с ease none, никаких tween по элементам, CSS-transition и таймеров; 2) движение на пружинах (файл phys.js), при нескольких сменах цели сумма пружин, крупные объекты без перелёта (демпфирование от 0,9), мелкие с лёгким перелётом (0,7–0,8); 3) одна форма перетекает из состояния в состояние, ничего не появляется и не исчезает отдельно; 4) живая камера: мир медленно наезжает или дрейфует, кадр не стоит дольше 2 секунд; 5) на фоне два мягких пятна света, плывут по синусу от t; 6) вход элемента: размытие 12→0, прозрачность, сдвиг 16–46 px на пружине, текст держится не меньше 1,5 с; 7) шрифт <название>, минимум 22 px, цифры табличные.
Все тайминги держи массивом T в начале скрипта и подпиши, к какому слову привязан каждый.
Фон прозрачный. Появление 0,15 с и исчезновение 0,3 с вшей в саму плашку. Рендер в 100 fps одним потоком, потом ffmpeg tmix=frames=4 до 25 fps, выход MOV ProRes 4444 с альфой плюс превью MP4 на тёмно-сером.
Проверка до сдачи, два круга: сделай лист кадров, посмотри глазами обрезку текста, наложения, мёртвые паузы, читаемость. Исправь, перерендерь, проверь ещё раз. Потом запусти субагента на независимую проверку.
Тексты только из этого задания, цифры не выдумывай.
```

## Команды рендера
Версия, на которой сделан ролик автора — `0.8.16`; при расхождении поведения сначала проверь на ней.
```
npx --yes hyperframes@0.8.16 check .
npx --yes hyperframes@0.8.16 render . -f 100 -w 1 -q high -o renders/scene_100.mp4 --quiet
```
Motion blur и 25 fps:
```
ffmpeg -y -i renders/scene_100.mp4 -vf "tmix=frames=4,select='not(mod(n\,4)-3)',setpts=N/25/TB" -r 25 -c:v libx264 -crf 16 -pix_fmt yuv420p renders/scene.mp4
```
Поверх видео: рендер с `--format mov`, в ffmpeg `-c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le` и выход `.mov`.
`-w 1` (один поток) медленнее, но машина не зависает — оставляй, если пользователь в это время работает.

## Повтор чужой анимации по видео
Кейс автора, демо интерфейса 14 с:

| | Заход 1 | Заход 2 |
|---|---|---|
| Что дали | только видео | видео + технику из промпта автора |
| Модель | Sonnet 5 | Opus 5.5 |
| Время | 16 мин | 14 мин + 3 мин доработки |
| Результат | заготовка: курсор мимо кнопок, интерфейс ~15% кадра, без blur | почти оригинал: одна форма, интерфейс ~77% кадра, честный blur |

**Вывод:** решает объяснённая техника и сильная модель, а не время. Промпт (приложить видео-образец, строку состояний заменить):
```
Собери моушн-ролик 14 секунд, 1080×1080, 60 fps, петлёй (последний кадр = первый). Референс — видео во вложении: разбери его покадрово и повтори ритм и превращения.
Техника, строго:
1. Один HTML-файл. Всё, что видно, считается в функции seek(t) из времени t. Никаких CSS-transition, setTimeout и состояния между кадрами.
2. Движение — пружины замкнутой формулой (переходная характеристика с жёсткостью и демпфированием). Если цель меняется несколько раз — сумма пружин, по одной на каждую смену. Крупные объекты без перелёта.
3. Один элемент без склеек перетекает через все состояния: <перечисли состояния из референса>.
4. Курсор — тоже сумма пружин, его цель в момент t берётся из геометрии элемента в тот же t. Клик: курсор коротко сжимается, элемент отжимается.
5. Камера масштабирует мир отдельной, более медленной пружиной: каждое состояние занимает ~60–75% ширины кадра.
6. Сетка 120 BPM: на каждую долю событие. Сначала составь таблицу долей.
7. Рендер Playwright на 240 fps, потом ffmpeg tmix=frames=4 → 60 fps.
Проверка до сдачи: отрендери по кадру на каждую долю и на полудоли, посмотри глазами, исправь, повтори. Сдай финал, сравнение «оригинал | копия» и отчёт: время, круги правок, что хуже оригинала.
```
Один в один не копируй: переноси технику на дизайн-систему пользователя (цвета, шрифты, скругления, параметры пружин в одном файле), чтобы все анимации канала были в одном стиле.

## Банк анимаций
- Каждая анимация — папка с `index.html` и рендером.
- Скрипт-оглавление обходит папки: путь, длительность, размер, есть ли тёмное поле слева под плашку, текст на плашке.
- Перед новой анимацией — поиск по оглавлению. Подошла по смыслу → копия папки + новые `T`. Так каждый следующий ролик дешевле.

## Картинки вместо анимации
Схемы, разбивки, иллюстрации — картинкой с медленным наездом. Плашка «картинка проявляется»: размытие 12→0, подъём на пружине, наезд на 6%, в конце гаснет; тёмное поле слева как у остальных плашек. Генерация в Codex CLI (встроенная генерация картинок) или в любом генераторе, который держит стиль:
```
codex exec -c model_reasoning_effort=low --skip-git-repo-check --sandbox workspace-write -C <папка> "<промпт>"
```
Если Codex ругается на модель — добавить `-m <модель из подписки>`. Шаблон промпта (стиль автора — замени цвета на свою дизайн-систему):
```
Use your image generation tool to create 2 different variants of the following illustration. Save them as PNG files exactly at: <путь>/name_v1.png and <путь>/name_v2.png. Do not write code to draw the images, use the image generation tool.
Style: flat editorial vector illustration. Background solid warm graphite #1e1b18 filling the whole canvas. All line art in warm milk #f6f0e6, thin even strokes. Exactly ONE accent color orange #e8743b on one or two key elements. Rounded capsule shapes, generous empty space, no shadows, no gradients, no glow, no 3D, no photorealism, no emoji. ABSOLUTELY NO text, letters, numbers or logos anywhere. Landscape 16:9. Main subject centered.
Subject: <что нарисовать и какая идея>
```
Текст — отдельным слоем поверх картинки, не в генерации.
